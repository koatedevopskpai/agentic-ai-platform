# V1 — Bound the public claims against verified evidence

## Why

The README describes a ReAct agent loop, a tool-use engine, an execution trace, a
Streamlit dashboard and a containerised deployment. CI proves a **narrower** thing than
that, and this project also carried an attribution error that was corrected on
18 October 2026. This task records what is verified, by what, and what is not.

## What actually runs

`.github/workflows/ci.yml`, on every push and pull request — a single job:

1. `pip install ".[dev]"`
2. `OPENAI_API_KEY=sk-test-dummy python -m pytest tests/ -v --tb=short`

There is **no lint step and no Docker build** in CI. Both are real gaps below.

## How the LLM is handled in tests

`tests/conftest.py` substitutes a `MockChatOpenAI` at the import path
(`src.services.agent_workflow.ChatOpenAI`) through an autouse fixture, and clears the
service's `lru_cache` so the patched client is used. The application code runs
unmodified — no dependency-injection branch, no test-only conditional.

The consequence is the boundary that matters: **no test in this repository makes a real
model call.** The stub returns a tool call on its first invocation and a final answer on
its second, which exercises the loop's plumbing but not the model's behaviour.

## The honest summary

This repository demonstrates a **working, unit-verified FastAPI agent orchestration
service**: the workflow endpoint runs end to end against a stub model, returns a
structured trace whose models validate, and rejects malformed input. It does **not**
demonstrate that the agent reasons well, selects tools appropriately, or that anything
here behaves as it would against a real model.

The distinction is the point of recording it: "ReAct agent loop" describes code that
exists and is exercised; it is not evidence that the loop produces good answers.

## What would close the gap

A recorded run against a real provider, on a fixed task set, publishing: the tasks, the
tools selected per step, whether results were used, and the final answers — plus a
deliberate failure case (tool error, or an iteration cap reached). Until that exists,
the LLM behaviour here is unverified.
